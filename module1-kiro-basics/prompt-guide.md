# 프롬프트 가이드

이제 프로젝트의 세부 사항을 Kiro에게 알려줄 차례입니다.

아래 프롬프트들을 **순서대로, 하나씩** 복사해서 Kiro 채팅창에 붙여넣으세요. 각 프롬프트를 보낸 후 Kiro가 응답하면 다음 프롬프트를 보냅니다.

---

## Step 1: 기술스택 알려주기

> 🤔 **기술스택이란?** 시스템을 만들 때 사용하는 도구와 재료의 목록입니다. 요리할 때 "가스레인지, 프라이팬, 올리브오일"을 정하는 것과 같아요.

{% code title="📋 복사해서 붙여넣기" %}
```
사용하려는 기술스택에 대해 먼저 설명합니다.
- Frontend: React (vanilla)
- Backend: Node.js Express (TypeScript)
- Database: SQLite (로컬 개발용)
- 주요 라이브러리: Chart.js (대시보드), date-fns (날짜 처리)
- Communication: REST API
```
{% endcode %}

<details>

<summary>💡 위 기술스택이 뭔지 궁금하다면?</summary>

| 용어 | 쉬운 설명 |
|------|-----------|
| **Frontend (React)** | 사용자가 보는 웹 화면을 만드는 도구 |
| **Backend (Express)** | 화면 뒤에서 데이터를 처리하는 서버 |
| **Database (SQLite)** | 상품, 재고, 주문 정보를 저장하는 창고 |
| **Chart.js** | 예쁜 차트/그래프를 그려주는 도구 |
| **REST API** | 화면(Frontend)과 서버(Backend)가 대화하는 방식 |

</details>

## Step 2: 데이터 구조 알려주기

> 🤔 **데이터베이스 테이블이란?** 엑셀 시트와 같은 것입니다. "상품 시트", "재고 시트" 등 정보를 종류별로 나누어 저장하는 표입니다.

{% code title="📋 복사해서 붙여넣기" %}
```
Database 테이블 설계입니다.
시스템은 총 4개의 테이블로 구성됩니다.

1. product - 상품의 기본 정보를 등록하고 관리합니다 (상품코드, 상품명, 카테고리, 단가, 최소재고량 등)
2. inventory - 각 상품의 현재 재고 수량과 최근 입고/출고 현황을 기록합니다.
3. sales_history - 일별/시간대별 판매 이력을 저장합니다. 발주량 예측의 기반 데이터입니다.
4. order - 자동 생성된 발주 내역을 저장합니다. (발주번호, 상품코드, 발주수량, 상태(대기/승인/취소), 생성일시)
```
{% endcode %}

<details>

<summary>💡 4개 테이블을 쉽게 이해하면?</summary>

| 테이블 | 엑셀로 비유하면... | 저장하는 정보 |
|--------|-------------------|-------------|
| **product** | 상품 마스터 시트 | 삼각김밥 800원, 도시락 4,500원... |
| **inventory** | 재고 현황 시트 | 삼각김밥 12개 남음, 도시락 3개 남음... |
| **sales\_history** | 판매 기록 시트 | 어제 삼각김밥 25개 팔림, 오늘 오전 10개 팔림... |
| **order** | 발주 시트 | 삼각김밥 50개 발주 (승인 대기중)... |

</details>

## Step 3: 원하는 기능 알려주기

{% code title="📋 복사해서 붙여넣기" %}
```
주요 기능은 다음과 같습니다.
- 자동 발주량 계산: 최근 7일 판매 데이터 + 현재 재고를 기반으로 발주 필요 수량을 자동 계산합니다.
- 발주 승인/수정: 점주가 웹에서 자동 생성된 발주를 확인하고 승인 또는 수량 수정할 수 있습니다.
- 재고 현황 모니터링: 실시간으로 상품별 재고 현황을 조회하고, 재고 부족 알림을 받을 수 있습니다.
- 판매 분석 대시보드: 카테고리별/시간대별 판매 트렌드를 차트로 시각화합니다. Chart.js를 사용합니다.
```
{% endcode %}

## Step 4: 실행 환경 알려주기

> 🤔 이 프롬프트는 "클라우드 서버 없이 **내 노트북에서** 바로 실행할 수 있게 해줘"라고 요청하는 것입니다.

{% code title="📋 복사해서 붙여넣기" %}
```
로컬 환경에서 빠르게 구축되는것을 목표로 합니다.
Database는 SQLite를 사용하고, 별도의 AWS 인프라 없이 로컬에서 백엔드와 프론트엔드가 모두 동작하게 해주세요.
판매 데이터 시뮬레이터를 만들어서, 웹페이지의 특정 메뉴에서 가상의 판매 데이터를 생성할 수 있게 해주세요.
```
{% endcode %}

{% hint style="info" %}
**판매 데이터 시뮬레이터**란? 실제 매장 데이터 없이도 테스트할 수 있도록, 버튼을 누르면 가짜 판매 데이터가 자동 생성되는 기능입니다.
{% endhint %}
